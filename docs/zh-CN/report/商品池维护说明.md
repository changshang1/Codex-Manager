# 商品池维护说明

## 当前产品范围

商品池目前只服务 PriceAI 的 **ChatGPT Plus 试用订阅**，代码标识为
`chatgpt-plus`。这是当前明确的产品决策，不是一个需要用户在页面上切换的筛选项。

页面不会显示产品下拉框，也不会显示商品源选择或数据源编辑表单。这样做是为了避免把
普号、正价代充、Team/Business 或不同抓取配置混在同一个列表中，导致价格、库存和提醒
的比较口径不一致。页面标题下方会标注“商品源由代码固定，避免混入其它产品”。

默认自动同步源如下，首次创建后会持久化到 SQLite：

| 配置 | 值 |
| --- | --- |
| 源 ID | `default-chatgpt-plus` |
| 产品 | `chatgpt-plus` |
| 标签 | `account_verified` |
| 定时同步 | 启用 |
| 自动二次验证 | 启用 |

`account_verified` 是 PriceAI 的标签，含义是已接码成品号，不是另一个商品源。页面首次
打开时默认使用这个标签筛选；清除筛选只能清除标签、价格、关键词等条件，产品仍固定为
Plus。

## 同步范围

产品和商品源是代码配置，不通过页面修改。若要改成其它产品，需要同步检查：

1. `apps/src/app/marketplace/page.tsx` 中的 `MARKETPLACE_PRODUCT_ID` 和显示名称。
2. `crates/service/src/marketplace.rs` 中的 `MARKETPLACE_PRODUCT_ID`、
   `MARKETPLACE_SOURCE_ID`、`MARKETPLACE_DEFAULT_TAGS_JSON` 以及默认源创建逻辑。
3. 已安装环境是否需要新增 SQLite migration，将旧默认源迁移到新的产品。
4. 前端 TypeScript、Rust service/Tauri 检查和商品池定向测试。

定时同步的范围不是代码常量。右上角“商品池设置”中的“定时同步”页可配置启用状态、
PriceAI 标签和自动二次验证。标签可多选，按 PriceAI 的严格 AND 逻辑请求；不选择标签
表示定时同步全部 Plus 商品。默认仍为 `account_verified`。保存时只更新这三项用户配置，
服务重启和读取商品源列表都不能把它们重置为默认值。

“立即同步全部”始终请求 `chatgpt-plus` 的全部分页，不携带任何标签，也不受定时同步
启用开关或页面展示筛选影响。自动同步和“立即同步全部”都会在完整抓取及校验成功后，
用本次结果集原子替换数据库中的全部商品报价。自动同步只保留符合已保存定时标签的本次
结果；“立即同步全部”保留全部 Plus 结果。PriceAI 明确返回合法的 `total=0` 时也作为有效
结果清空报价；请求、标签范围、分页、字段或写入失败时整体回滚并保留同步前数据。

服务端自动轮询只处理固定的 `default-chatgpt-plus` + `chatgpt-plus` 源。旧数据库中的
其它源配置不会继续参加自动轮询；其遗留报价会在下一次成功同步时清理，不需要数据库迁移
或手动删除数据库文件。替换不会删除商品源配置、提醒规则、变化记录、收藏商家或商品池设置。
相同商品 ID 继续更新原记录，保留首次发现时间、本地验证结果和提醒 baseline；未返回商品
及其提醒运行状态会删除，并且不会新增“已移除”变化记录。

## 页面筛选

页面进入后默认显示当前报价中的 Plus + `account_verified`。顶部直接可用的条件包括：

- 包含关键词
- 最低价、最高价
- PriceAI 原始状态
- 本地验证状态

快捷筛选包括库存至少 50、最近 1 小时更新和 PriceAI 标签。展开筛选还包含渠道来源、
Plus/Team 标签组、最低库存、1/6/24 小时更新时间和排除关键词。多个标签是同时满足，
排除关键词命中任意一项就排除。

列表只显示当前数据库结果，并依次按“本地验证可用、PriceAI 可用、价格从低到高”排序。
页面不再提供“历史/未返回”入口；已有变化记录继续在商品池设置中保留。同步刷新底层数据时
不会重置关键词、价格、状态、快捷标签或收藏商家等页面展示筛选。

## 收藏商家

报价表的商家列提供星标按钮。收藏以商家为单位持久化到 SQLite 的
`marketplace_favorite_merchants` 表；同一商家的全部报价共用收藏状态，应用重启后仍保留。
快捷筛选中的“只看收藏商家”只改变当前列表展示，清除筛选会关闭该条件，但不会删除收藏。

商家标识由后端统一计算并随报价返回，前端不自行拼接：优先使用 PriceAI 的
`collectorKind + sourceId`；少数缺少这两个字段的报价，使用“商品链接 origin + 商家名”
作为降级键。信息仍不足时禁用星标，避免仅按同名商家或共享售卖平台域名造成误合并。

第一版收藏只用于星标和本地筛选，不改变手动/自动同步范围，不自动创建提醒规则，也不会
因为收藏而发送桌面通知。对应 schema migration 是
`131_marketplace_favorite_merchants.sql`。

## 提醒、通知和变化记录

右上角“商品池设置”是页面内抽屉，包含“定时同步、提醒规则、桌面通知、变化记录”四页。
提醒规则仍可配置价格、降价金额/比例、标签、商家、缺货变有货、验证状态变化和链接失效
等条件；产品范围固定为 Plus。若定时标签不能完整覆盖某条规则的商品集合，页面会显示提示。
覆盖关系为：定时标签集合为空，或定时标签集合是规则标签集合的子集。

手动同步只更新商品和变化记录，不进行二次验证，也不发送桌面通知。自动同步由服务启动
时执行一次，之后每小时执行一次，会按规则验证和评估提醒。首次自动同步只建立 baseline，
持续满足条件不会重复通知，离开条件后再次满足才会再次通知。

自动二次验证默认覆盖本次报价按价格升序的前 20 个，以及产品、来源、标签、商家和价格
范围可能命中任一提醒规则的报价。报价行上的“立即验证”只验证该商品并更新本地状态和变化
记录，不重新抓取 PriceAI 全量数据，也不发送桌面通知。

## 状态字段

每个报价分别保存 PriceAI 原始状态、本地验证状态、最后验证时间和验证失败原因。页面上
的 PriceAI 状态不会被本地验证结果覆盖；本地验证只读取商品页/渠道接口，不绕过验证码、
登录墙或 WAF，也不执行购买。

PriceAI 状态按其公开接口字段计算，而不是按“点进购买页能否下单”反推：

1. `status=out_of_stock` 显示“缺货”。
2. 价格无效或商品 URL 缺失显示“状态异常”。
3. `effectiveStatus=failed` 或 `freshnessStatus=failed` 显示“状态异常”。
4. `effectiveStatus=unavailable/stale`、`freshnessStatus=expired`，或 `expiresAt` 已过期，
   显示“暂不可用”。
5. 其它情况显示“有货”。

`stockCount=0` 不会单独覆盖 PriceAI 的 `status=in_stock`；这是对 PriceAI 官方
`isAvailable` 语义的兼容。真实购买页可能因库存延迟、登录、验证码或渠道状态而不可购买，
因此本地验证单独展示，永远不覆盖 PriceAI 列。

报价还保存 PriceAI 返回的 `sourceIncludedAt` 和 `sourceShopCreatedAt`，页面分别显示商家
“收录多久”和“公开运营多久”。任一字段缺失或时间无效时只隐藏该项，不使用另一项替代；
PriceAI 临时漏字段时保留数据库中上次已知的有效时间。这两个原始时间由 PriceAI 商品接口
直接返回，不使用 CodexManager 的 `first_seen_at` 推算；前端只负责把时间戳换算成“今天”、
“N 天”、“N 个月”或“N 年”的展示文案。
