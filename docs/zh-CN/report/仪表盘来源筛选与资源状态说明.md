# 仪表盘来源筛选与资源状态说明

本文说明账号池和聚合 API 的人工启停、健康状态、页面顺序，以及管理员仪表盘的来源筛选
口径。页面显示顺序、运行时可用性和模型路由优先级是三套独立概念，不能互相替代。

## 账号池的允许接入与健康状态

账号池每行的“允许接入”开关只控制人工停用：

- 关闭后，账号状态写为 `disabled`，不会参与请求。
- 打开后，先恢复允许接入，再立即刷新用量验证账号健康。
- 刷新失败或无法执行时，允许接入仍保持开启，健康状态明确写为 `unavailable`。
- 只有后续用量刷新拿到新的综合可用快照，账号才恢复为 `active`；额度耗尽时会进入
  `limited`，不需要再次切换开关。

快速开启使用 `markUnavailableOnFailure=true`，用于确保“验证失败的账号不能立即参加请求”。
普通单账号刷新、批量刷新和后台轮询默认不启用这个失败隔离参数，避免一次临时网络错误把
原本可用的账号批量改成不可用。

因此，“开关已打开”不等于“账号当前可用”。实际是否参与请求仍取决于 token、账号状态、
额度快照和网关健康判断。账号列表先显示可用账号，再显示不可用账号；每组内部继续按账号
顺序号显示。组内上移或下移只交换本组已有的顺序槽位，不会打乱另一组。

## 聚合 API 的状态与显示顺序

聚合 API 页面保留快速启停开关，并增加“顺序”列和上移、下移按钮。移动后通过
`aggregateApi/updateSorts` 在一个 SQLite 事务中保存整组顺序；编辑连接时仍可直接填写
`sort`。

连接的 `sort` 只控制聚合 API 管理页和选择列表的显示顺序，不参与真实请求。运行时模型
route 的主备层级和流量比例分别由 `priority` 与 `weight` 决定，详情见
[聚合 API 请求规则与配置说明](聚合API请求规则与配置说明.md)。

## 仪表盘来源筛选

管理员仪表盘的“统计来源”筛选同时作用于 Token、请求、费用、趋势、模型统计和账号池
剩余。支持：

- 全部来源、账号池或聚合 API。
- 具体账号与具体聚合 API 任意多选，也可以混合选择。
- 按账号名称、来源 ID 或聚合 API 名称搜索，并分页加载。
- 具体来源按区间 Token 降序、名称、来源类型和来源 ID 稳定排序；勾选只改变筛选条件，
  不会把已选项移动到列表顶部。
- 默认包含不可用和已删除来源，保证历史用量仍能查到。
- 关闭“包含不可用来源”后，从本次统计中排除当前不可用、已停用或已删除的来源。

没有选择具体来源等价于当前来源类型下的全部来源。来源用 `(sourceKind, sourceId)` 复合键
区分，避免账号 ID 与聚合 API ID 相同导致串数据。筛选在 SQLite 聚合前执行，不是前端拿到
全局总数后再隐藏行。

日期快捷选项包含“今日”。“今日”按本机自然日计算，并每分钟推进结束时间；自定义日期仍
要求结束时间晚于开始时间。

## 费用口径

仪表盘“费用”是 CodexManager 的本地美元成本估算，不是 OpenAI 或聚合 API 供应商返回的
账单、扣款或余额变化。网关按请求实际 usage 记录输入、缓存输入和输出 Token，再使用模型
目录 V2 当前命中的价格阶梯计算：

```text
未缓存输入 × 输入单价 + 缓存输入 × 缓存输入单价 + 输出 × 输出单价
```

单价按每百万 Token 计。结果写入 `request_token_stats.estimated_cost_usd`，仪表盘再按日期和
来源求和。上游没有返回 usage 时，输入 Token 可能按请求正文做本地估算；模型价格缺失或
计费快照失败时，该请求费用按 0 汇总。这里展示的是基础成本，不包含成员钱包或模型组倍率。

## 账号池剩余口径

“账号池剩余”只汇总当前筛选范围内真正可用账号的最新额度快照。不可用账号不会作为 0%
参与平均值，因此一个满额度可用账号加一个不可用账号不会再显示成 50%。

空状态区分两种情况：

- “当前筛选无账号”：所选来源范围里没有账号。
- “暂无可用账号”：范围内存在账号，但没有可参与汇总的可用账号。
